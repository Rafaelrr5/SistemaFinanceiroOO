\section{Descrição do Sistema}
% ============================================================

O sistema desenvolvido é uma aplicação para \textbf{gestão de carteiras de investimento}, permitindo que investidores (pessoas físicas ou institucionais) gerenciem seus ativos financeiros. O sistema suporta diversos tipos de ativos: \textbf{Ações}, \textbf{FIIs} (Fundos de Investimento Imobiliário), \textbf{Stocks} (ações internacionais), \textbf{Criptoativos} e \textbf{Títulos do Tesouro}.

As principais funcionalidades incluem:
\begin{itemize}[noitemsep]
    \item Cadastro, edição e exclusão de ativos e investidores;
    \item Registro de movimentações de compra e venda;
    \item Cálculo automático de preço médio de compra;
    \item Conversão de ativos internacionais para Reais;
    \item Geração de relatórios com análise de diversificação;
    \item Importação de dados em lote via arquivos CSV.
\end{itemize}

\section{Conceitos de Orientação a Objetos Aplicados}
% ============================================================

\subsection{Herança e Abstração}

A classe \texttt{Ativo} é \textbf{abstrata} e serve como base para os tipos específicos de ativos:

\begin{itemize}[noitemsep]
    \item \texttt{Acao} -- Ações brasileiras (renda variável, nacional)
    \item \texttt{FII} -- Fundos Imobiliários (renda variável, nacional)
    \item \texttt{Tesouro} -- Títulos do Tesouro Direto (renda fixa, nacional)
    \item \texttt{Stock} -- Ações internacionais (renda variável, internacional)
    \item \texttt{Criptoativo} -- Criptomoedas (renda variável, internacional)
\end{itemize}

Da mesma forma, \texttt{Investidor} é uma classe abstrata com duas especializações:
\begin{itemize}[noitemsep]
    \item \texttt{PessoaFisica} -- com perfil de investimento (Conservador, Moderado, Arrojado)
    \item \texttt{Institucional} -- com razão social e sem restrições de movimentação
\end{itemize}

\subsection{Interfaces}

Foram definidas três interfaces que garantem contratos específicos:

\begin{itemize}[noitemsep]
    \item \texttt{AtivoNacional} -- define o método \texttt{getPrecoEmReais()};
    \item \texttt{AtivoInternacional} -- define \texttt{converterParaReais()} e \texttt{getFatorConversao()};
    \item \texttt{Investimento} -- define \texttt{cadastrarInvestimento()} e \texttt{podeMovimentar()}.
\end{itemize}

\subsection{Encapsulamento}

Todos os atributos das classes são \textbf{privados}, acessados exclusivamente por métodos \textit{getters} e \textit{setters}. Validações são realizadas nos setters e nos serviços antes de qualquer modificação de estado.

\subsection{Polimorfismo}

O método \texttt{podeMovimentar(Ativo)} é implementado de forma diferente em \texttt{PessoaFisica} (aplica restrições por perfil) e \texttt{Institucional} (sem restrições), permitindo que o sistema trate investidores de forma uniforme.

\section{Regras de Negócio Implementadas}
% ============================================================

\subsection{Validações de Ativos}
\begin{itemize}[noitemsep]
    \item Ticker não pode ser nulo ou vazio;
    \item Preço deve ser maior que zero;
    \item Ao excluir um ativo, ele é removido de todas as carteiras de investidores.
\end{itemize}

\subsection{Validações de Investidores}
\begin{itemize}[noitemsep]
    \item Nome e CPF/CNPJ são obrigatórios;
    \item CPF deve ter 11 dígitos e CNPJ deve ter 14 dígitos (validação de formato);
    \item Patrimônio não pode ser negativo;
    \item Ao excluir um investidor, sua carteira também é removida.
\end{itemize}

\subsection{Regras de Movimentação}
\begin{itemize}[noitemsep]
    \item \textbf{Criptoativos}: apenas investidores com perfil \textit{Arrojado};
    \item \textbf{Stocks}: perfil \textit{Moderado} ou \textit{Arrojado};
    \item \textbf{Ativos qualificados}: apenas investidores com patrimônio $\geq$ R\$ 1.000.000,00;
    \item \textbf{Institucional}: pode movimentar qualquer ativo sem restrições;
    \item \textbf{Vendas}: não podem exceder a quantidade disponível na carteira.
\end{itemize}

\subsection{Cálculo de Preço Médio}

Ao comprar um ativo já existente na carteira, o preço médio é recalculado:
\[
\text{PM}_{\text{novo}} = \frac{(\text{Qtd}_{\text{antiga}} \times \text{PM}_{\text{antigo}}) + (\text{Qtd}_{\text{nova}} \times \text{Preço}_{\text{compra}})}{\text{Qtd}_{\text{antiga}} + \text{Qtd}_{\text{nova}}}
\]

\section{Tratamento de Exceções}
% ============================================================

Foi criada a exceção personalizada \texttt{RegraNegocioException} (estende \texttt{RuntimeException}) para tratar violações de regras de negócio de forma clara e específica.

Exemplos de uso:
\begin{itemize}[noitemsep]
    \item Tentativa de venda maior que a quantidade disponível;
    \item Investidor conservador tentando comprar criptoativos;
    \item Cadastro de ativo com preço negativo ou zerado;
    \item CPF/CNPJ com formato inválido.
\end{itemize}

\section{Funcionalidades de Relatório}
% ============================================================

O sistema gera relatórios em formato \textbf{JSON} contendo:

\begin{itemize}[noitemsep]
    \item Dados do investidor (nome, CPF/CNPJ, patrimônio);
    \item Lista de ativos na carteira com quantidade, valor gasto e valor atual;
    \item Valor total gasto e valor total atual;
    \item Percentual de renda fixa vs. renda variável;
    \item Percentual de ativos nacionais vs. internacionais;
    \item Data e hora de geração do relatório.
\end{itemize}

\section{Testes e Validação}
% ============================================================

Foram implementados testes unitários utilizando \textbf{JUnit 5} para validar:
\begin{itemize}[noitemsep]
    \item Criação e manipulação de ativos;
    \item Regras de permissão de movimentação por perfil;
    \item Operações de compra e venda na carteira;
    \item Cálculos de diversificação (renda fixa/variável, nacional/internacional);
    \item Validação de documentos (CPF/CNPJ).
\end{itemize}

O sistema foi testado com arquivos CSV de exemplo contendo ações, FIIs, stocks, criptoativos e títulos do tesouro, demonstrando o correto funcionamento da importação em lote.

\section{Conclusão}

O sistema desenvolvido atende integralmente aos requisitos especificados, aplicando de forma consistente os princípios de Orientação a Objetos: \textbf{herança}, \textbf{abstração}, \textbf{encapsulamento}, \textbf{polimorfismo} e \textbf{interfaces}.
