\section{Decisões de Implementação}

O sistema foi desenvolvido na linguagem \textbf{Java}, utilizando conceitos de orientação a objetos (herança, abstração, encapsulamento e interfaces). As principais decisões técnicas foram:

\subsection{Estrutura de Pacotes}
\begin{itemize}
    \item \textbf{model}: classes de domínio (Ativo, Investidor, Movimentação, Carteira).
    \item \textbf{service}: regras de negócio e validações.
    \item \textbf{repository}: armazenamento em memória.
    \item \textbf{ui}: interface em console.
    \item \textbf{exception}: exceções personalizadas.
\end{itemize}

\subsection{Validações}
\begin{itemize}
    \item Ativos não podem ter preço nulo ou negativo.
    \item Investidores não podem ter patrimônio negativo.
    \item Vendas não podem exceder a quantidade disponível na carteira.
    \item Apenas investidores qualificados (patrimônio $\geq$ R\$1.000.000,00) podem operar ativos restritos.
\end{itemize}

\subsection{Relatórios}
O sistema gera relatórios em formato \textbf{JSON}, contendo:
\begin{itemize}
    \item Valor total gasto e valor atual da carteira.
    \item Percentuais de renda fixa/variável.
    \item Percentuais de ativos nacionais/internacionais.
\end{itemize}

\section{Análise Comparativa das Funcionalidades}

O sistema foi testado com arquivos CSV de ativos e investidores. Observou-se:
\begin{itemize}
    \item \textbf{Cadastro em lote}: eficiente para grandes volumes de dados.
    \item \textbf{Relatórios}: permitem análise clara da carteira.
    \item \textbf{Movimentações}: respeitam regras de negócio e impedem inconsistências.
\end{itemize}
